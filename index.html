01 LIVE

Command Center — the whole jobsite on one sheet.

The consolidation hub for the LACC concrete team. One role-aware map that unifies CUP footings and EmbedYap pins, plus RFIs, inspections, schedule, tools, and crew — rebuilt in June 2026 from a read-only sheet mirror into the team's operating picture.

Problem

The ecosystem got big. Each tool solved its own problem, but the superintendent's actual question — "what's ready for inspection, where are the embeds on F21, who's on site today" — crossed four apps. And the original Command Center only mirrored spreadsheets; it couldn't answer, only display.

Approach

Full rebuild as a consolidation hub. Still a static GitHub Pages SPA, but now reading the live Firebase namespaces of CUP, EmbedYap, Tool Tracker, and SuperYap — writing only to its own. Role-gated by Firebase Auth (Admin › Super › PM › PE, 2FA on Admin) with a global edit lock, so view-only is the default on every field device.

  • The Map — footings + embeds + pours + RFI zones + markups as toggleable layers on one pan/zoom canvas
  • RFIs — drag-and-drop a PDF, it links to Drive and pins to its map zone
  • Inspections — Ready → Pass/Fail sign-off stages that log who marked ready
  • Schedule — Excel import/export, synced to SuperYap's look-ahead
  • Live tools + crew pulled from the shared Firebase, role-filtered per tab
The workspace

Nine views behind one login — DASHBOARD · THE MAP (LIVE) · SCHEDULE · INVENTORY · RFIS · POURS · SUBMITTALS · ATTENDANCE · ADMIN. It's a true central workplace: the day starts here, and the other apps became its deep-edit tools. Click a footing on the Map and CUP opens to that pour; click an embed and EmbedYap opens to that pin.

Result

The featured tile on the launcher and the morning tailgate's one URL. The superintendent sees his layers, the PM sees her RFIs, the PE edits data — same map, different permissions. The original sheet-mirror version is preserved as a legacy tile.

02 LIVE

CUP Dashboard — a real-time view of the pour from any device.

Real-time concrete-pour platform for the LACC project. Pour plans, embed verification, live trucks, mix designs, inspection ticker, and a camera-driven bulk PDF scanner — all synced across every device in the field.

Problem

On a pour day you have 50+ moving parts: concrete trucks arriving, rebar placement status, embeds to verify, inspectors to coordinate, and a PM chewing through a printed footing map. The existing tools were: a spreadsheet, a clipboard, and walkie-talkies.

Approach

Static GitHub Pages SPA. Pour ticket indexing now uses Drive as the source of truth (we dropped the Firebase write path for tickets — fewer moving parts, audit trail in the sheet). Foremen drag footing shapes on the map, long-press embeds to step through a checklist, tap a truck arriving to log it live, and a new bulk scanner uses the camera + edge detection to ingest multi-page ticket PDFs.

  • Footing map with drag-edit + SVG status dots (green / amber / red-pulse)
  • Live Pour tab — donut chart, truck log, inspection ticker (?view=live)
  • Embed tracker with 10 CUP types (51A–90A) + long-press checklist popup
  • Mix design panel — PSI, aggregate, slump, LC3 cement
  • Bulk scanner — live camera feed + edge detection for multi-page PDF ingest
  • Apps Script → Sheet write-back for auditability
  • Alfred chat embedded with embed + mix-design context injection
Ties into the system

SuperYap's look-ahead feeds the pour dates; EmbedYap's install states surface on each footing's pre-pour checklist; Command Center mirrors the whole footing map as the base layer of its unified view.

Impact

Three sections of pour tracked end-to-end, live on the trailer iPad every morning. Inspectors confirm embed placement without a site visit, and the superintendent and project executive read pour status off the same screen the foremen update.

03 LIVE

EmbedYap — 299 embeds, zero guesswork.

Every anchor bolt and knife plate in the foundation, extracted from the plan PDFs with computer vision and tracked as live pins on a pan/zoom map. Miss an embed before a pour and you're coring concrete; EmbedYap exists so that never happens.

Problem

The embed plan was a PDF, a highlighter, and somebody's memory. 299 embeds across 75 types had to be installed in the right footing before each pour — and a missed one isn't a redo, it's a core drill through cured structural concrete with an engineer's sign-off. Status lived in whoever walked the deck last.

Build

A Python + OpenCV pipeline reads the structural plan PDFs — classifying the orange install dots and OCR-ing the red type labels — and seeds Firebase with 299 georeferenced pins across 75 embed types. The front end renders them on a pan/zoom canvas map: green installed, red to-install, amber next in sequence, blue knife plates. Originally React; I later ported it to a tiny vanilla-JS runtime — same UX, no framework, no build step, faster on trailer iPads.

  • CV/OCR extraction: plan PDF → classified pins, no hand-plotting
  • Canvas-rendered pins with marquee multi-select and manager markup tools
  • RFI attach on any pin — the drawing question travels with the embed
  • Dashboard, inventory, Excel/PDF export, and a crew leaderboard
  • React → vanilla runtime migration cut load time on field devices
Ties into the system

Command Center reads the pin namespace and layers every embed onto the unified map; clicking a pin there deep-links back into EmbedYap for the heavy edits. CUP's pour checklists reference the same install states.

Impact

Embed status stopped being tribal knowledge. The pre-pour walk is a filter ("show me red pins in F21"), the leaderboard made installs a competition, and no embed has been cored out since it shipped.

04 LIVE

Tool Tracker — the conex stopped lying.

An Assets-as-truth equipment registry for the field: orders, receiving, per-foreman checklists, a lost-tool log, and on-site verification. The workflow it replaced — ToolHound exports stapled to printed count sheets — lost roughly 65 tools in a single cycle.

Problem

Tool accountability ran on printouts taped to the trailer wall: a ToolHound export, re-keyed by hand, out of date the moment it printed. Tools moved between the conex, the deck, and foremen's trucks all day; the paper never followed. Across the previous cycle, about 65 tools simply disappeared — replacement cost plus the PM hours spent hunting them.

Build

A Firebase-backed registry where the Assets list is the single source of truth. ToolHound CSV/PDF imports reconcile against it with alias resolution (the same drill has four names in four systems); assignments log who has what; a "verified on site" checklist catches missing or mis-tagged tools before they walk. The same data drives a printable bilingual 11×17 count poster for the trailer wall — print catching up to digital instead of fighting it.

  • Assets-as-truth registry with alias resolution across import formats
  • Orders & receiving flow — new tools enter the registry, not a spreadsheet
  • Per-foreman 11×17 checklists, bilingual EN/ES, printed from live data
  • Lost-tool log with an all-time count and value-on-site rollups
  • On-site verification writes back to the sheet — the audit is the workflow
Ties into the system

Command Center's Inventory view and SuperYap's Tools tab both read this registry live — the superintendent sees the same asset truth next to the schedule that needs it.

Impact

The ~65-tools-per-cycle bleed stopped: every tool now has a holder, a location, and a verification date. The count that used to take a morning of walking with a clipboard is a filter and a printout.

05 LIVE

SuperYap — the superintendent's whole week on one sheet.

The superintendent suite: a three-week look-ahead builder plus live Attendance and Tools tabs, reading the same shared Firebase as the rest of the set. The schedule that used to take an afternoon now regenerates in minutes.

Problem

The look-ahead is the superintendent's core artifact — the sheet that tells forty people what happens for the next three weeks. Ours was redrawn by hand in Excel every week: chained dates recomputed manually, weekends and holidays skipped by eye, then an hour of formatting to match the Webcor standard before it could go on the wall.

Approach

A schedule builder that thinks in working days. Activities chain off each other or take manual dates; change one duration and everything downstream recomputes, skipping weekends and holidays automatically. Repeating pour cycles drop in with one Insert Cycle click, and activities link to their CUP pours so schedule and field status agree.

  • Chained or manual dating with a working-day engine (weekends + holidays skipped)
  • Insert Cycle — a whole repeating pour sequence added in one action
  • One-click export to the Webcor-format look-ahead: PDF for the wall, Excel for the PMs
  • Attendance tab reads Foreman Sign-In live — who's on site today, not last week
  • Tools tab reads Tool Tracker assets — the conex inventory next to the schedule that needs it
Ties into the system

Schedule activities link to CUP pours, Command Center syncs the look-ahead as the project's schedule truth, and the Attendance and Tools tabs read Foreman Sign-In and Tool Tracker live.

Impact

The weekly afternoon of Excel surgery is gone. The look-ahead prints in the Webcor format the office expects, and the superintendent edits dates instead of redrawing sheets.

06 FLAGSHIP

Mr. George — a project-engineer assistant on every channel I work in.

Internally codenamed Mr. George. Seventeen AI agents that read my emails, write my submittals, search 200+ drawings, dispatch to a research panel, and page me on Discord when something breaks. The const-agent web UI is the cockpit.

Problem

A project engineer on a $2B job spends most of their day shuffling: copying RFI responses into trackers, searching drawings for one detail, drafting submittal cover letters, chasing down inspector confirmations. LLMs are good at every one of these tasks individually. Nobody had wired them together for construction PM yet.

Approach

Built a multi-channel agent framework in Python. The same 17 agents — submittal coordinator, RFI triager, schedule analyst, drawing indexer, takeoff specialist, tool tracker, foreman roster, advisory panel of five — answer in Discord, Teams, and a dedicated web UI. Each channel routes to the right agent based on the message.

Model providers are hot-swappable: Anthropic (Claude Opus), OpenAI (Codex via ChatGPT OAuth), MiniMax M2.7, Gemini, Ollama for local. If one goes down, the next provider picks up. Vision is enabled — paste an image directly into Alfred and he'll read it.

  • Dispatch agent analyzes intent, routes to one of 17 specialists
  • Advisory panel: 5 research agents + a manager, all with Drive folder routing
  • Multi-vault routing — personal brain (192 notes) + project brain (25 LACC notes)
  • Sheets create / append / format from chat (Submittal, RFI, Tools, Embed trackers)
  • Drawing indexer runs fitz + pdfplumber + Gemini over 200+ sheet PDFs
  • Voice channel via ElevenLabs (Daniel / Charlie) + Web Speech API mic
  • Tool tracker assets-sync UI shipped today (4/29) — drop a ToolHound xlsx, click Sync
  • macOS Keychain for all provider keys — zero secrets in git
Every node in the brain is a markdown file. Every connection is a wikilink. Alfred reads them, links them, and surfaces the right one when you ask. The user authors the brain by editing .md files in Obsidian — the AI is just the librarian.
Result

Cuts a typical RFI/submittal prep from ~40 minutes to ~6. Drawing-search questions that used to take 10 minutes of sheet-flipping get answered in seconds. The Tools tab now ingests a ToolHound asset report and reconciles to the Assets sheet in one click. The full audit trail lives in SQLite — every question, every response, every tool call.

07 LIVE

Formwork — a budget tool built around the way construction teams already think.

OpenYap's own budget tracker. Categories sit inside formwork bays; planned spend reads as concrete pouring into each section; line items show as studs in the form. Underneath the metaphor: a Sankey flow view, a Cmd-K palette, a health gauge for variance against plan, and a 3D lattice for the compare view.

Problem

Running a venture means tracking every dollar of the $1.2M seed across LLC / legal / infra / dev / marketing / ops. Spreadsheets work but don't let you think in line items inside each budget, and they don't show the flow of money. I wanted a construction-native UX for money.

Approach

Firebase-backed single-file app. Each category drills into line items with statuses (planned / committed / done). The Plan view toggles between a Sankey flow and a Grid; scenarios let you fork the budget for what-ifs; Cmd-K palette hops to anything; a health gauge surfaces variance against plan in one glance. The Nodes view is a 3D formwork lattice — wireframe bays sized by planned total, concrete fill ∝ actual spend.

  • Sankey Plan view + Flow / Grid mode toggle
  • Scenarios — fork the budget, compare side-by-side
  • Cmd-K command palette to jump anywhere
  • Health gauge — variance against plan, at a glance
  • 3D formwork lattice (Compare view) and Excel export for compliance
Result

Live across devices, with the budget editable by anyone the project gives access to. Renamed from "Lumino" to "Formwork" so the tool's name lines up with the work it's tracking. The board now reviews budget plans the same way they'd review a pour schedule.

08 LIVE

OpenYap Roadmap — the investor deck as a building.

A scroll-driven 3D construction site that reads as the OpenYap pitch deck. Each section of the page builds a floor of the tower; a lattice crane climbs alongside the scroll position. We deploy two themes so we can match the audience.

Problem

A five-phase business plan delivered as slides loses people on slide three. We wanted a version of the same content that an investor or board member could absorb in roughly ninety seconds without giving it their full attention.

Approach

Three.js scene locked behind a WebGL shader background. 45 floors of glass assemble as you scroll, a lattice crane climbs with them, 800 particles drift, 13 material stacks tilt and shadow. GPU is auto-detected so the experience scales from a phone to an M3 Max without dropping frames.

  • Scroll position → camera & assembly progress
  • Aurora shader mesh gradient background
  • Floating node network (80 nodes, orbital connections)
  • Glassmorphic agreement panels with floor-highlight on hover
  • GPU auto-detection + aggressive perf tuning
  • Stitch variant — alternate theme for cleaner-skin audiences
Result

Presented to the Webcor board; the scroll-to-build animation got the room engaged in a way the slide version hadn't. Hero stats now reflect the current plan: $1.2M seed, 1,000%+ projected ROI, $432M+ Y5 TAM. Two themes are deployed so we can match the meeting.
